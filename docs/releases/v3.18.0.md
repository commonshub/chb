# v3.18.0 — Odoo URIs, trusted Nostr annotations, public photos

## One identifier per Odoo document

Every Odoo document is identified everywhere by its URI,
`odoo:<host>:<db>:<model>:<id>` (`account.move` for bills, credit notes and
invoices, `hr.expense` for expense claims not booked yet):

- `uri` on every entry of `expenses.json` and `pending-bills.json`, and on
  every `bookings.json` `rentals[]` row (the invoice), in every tier, month
  and year;
- `customers.json` rows list their invoices as `invoices: ["odoo:…"]`,
  anonymous merged rows included. **Breaking:** the invoice count moved to
  `invoiceCount` (it was `invoices` since v3.16);
- the audience policy allows Odoo URIs below stewards and now explicitly
  refuses Stripe customer ids (`cus_…`) there; members transactions and
  counterparties no longer carry `stripe:cus_…` ids;
- `id` (`b-…`, `x-…`) stays one more release as a deprecated alias.

## Nostr annotations: the right relay, a trust list, no comments

- Default relay `wss://relay.commonshub.brussels` for reading and
  publishing (settings.json `nostr.relays`); `nostr.commonshub.brussels`
  (503) and public relays are no longer used. `keys/nostr.json` `relays`
  is ignored.
- Annotations apply only when signed (signature verified) by an author in
  settings.json `nostr.trustedAuthors`, seeded with the website's key and
  chb's own; the newest trusted snapshot per URI wins; others are ignored.
- An annotation is kind 1111 with lowercase `i`/`k` only. chb no longer
  publishes uppercase `I`/`K` (NIP-22 comments), and never applies an event
  that carries `I`, so a website comment can no longer overwrite a
  description.
- `chb pull` (hourly) fetches every trusted annotation since the last pull
  in one query, read-only and without keys (prod could not read
  annotations before), and files them by URI: transactions in
  `transaction-annotations.json`, bills, invoices and expense claims in the
  new `odoo-annotations.json`. `chb generate` applies them to
  `transactions.json` (`metadata.note` for the text), `expenses.json`,
  `pending-bills.json` and room rentals (`note`). The pull no longer
  publishes anything.
- The first pull after upgrading is a full one and replaces the cached
  annotations; annotations previously fetched from other relays, or with
  `I` tags, are dropped. Generate also ignores any cached annotation whose
  author is not trusted.

## Photos from public channels, served from public/

- settings.json `discord.publicChannels` (default `general`,
  `activities.contributions`, `activities.tokens`): only their photos appear
  in `public/images.json`.
- `chb images sync` copies those photos to
  `YYYY/MM/public/images/<attachment id>.<ext>` (0755/0644) and removes
  copies from channels that are no longer public; `filePath` in the public
  and members `images.json` points there. The Discord `url` stays.

Backfill once: `chb images sync --history --force`, then
`chb generate --history --force`.
