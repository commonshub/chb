# v3.10.1 — Gnosis via Blockscout, delta fetches, quota fallback

## Why

On 2026-09-07 Etherscan's free plan stopped serving Gnosis (chain 100):
every hourly `chb pull` on prod logged `Free API access is not supported for
this chain` for all 8 Gnosis accounts, so no EURe/EURb movement reached the
local mirror (and therefore Odoo) after that date. Celo (CHT) separately hit
`Community Free API Limit reached` each evening, because every hourly run
re-downloaded the full history from `startblock=0`.

## What changed

- **Blockscout as a second explorer** (`providers/etherscan/explorer.go`).
  Same Etherscan-compatible query and response shape, no key. Gnosis goes to
  `gnosis.blockscout.com` directly (Etherscan refuses it); Celo stays on
  Etherscan and falls back to `celo.blockscout.com` when Etherscan declines
  on plan/quota grounds. Genuine errors (bad key, 4xx) still fail. Blockscout's
  empty sentinel (`No token transfers found`) now reads as "nothing new".
- **Delta fetches.** The routine (non-forced, non-backfill) sync now passes
  `startblock=<newest cached block>` and merges the answer into the month
  file (`MergeTokenTransfers`, dedup by transfer key, newest-first). One small
  request per account per hour, usually empty — instead of a peek plus the
  full history. Forced, backfill and enrichment-refresh runs still fetch
  everything.

## Verification

Live: `chb accounts checking pull` recovered the 7 EURe transfers missing
since Aug 17 (Sep 7 ×4, Sep 14 ×3); the re-run is a 4s no-op with 0 new.
Unit tests cover endpoint selection, the no-key Blockscout query, the empty
sentinel, quota fallback vs. genuine errors, month merging and the cached
block lookup.
