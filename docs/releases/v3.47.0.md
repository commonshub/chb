# v3.47.0 — No more bare "mint EURe" lines in Odoo

**`chb odoo sync` heals bare lines by itself.** A statement line still
labelled "mint EURe" / "burn EURe" whose Monerium order has since reached
the local cache gets its real payment_ref (the payer's memo), narration and
partner at the next sync, found offline in the journal cache:

- a categorised line (revenue, expense, 580000) is relabelled and keeps its
  account; the reconcile that follows sees the reference, so a payment
  booked to revenue is matched to the invoice it names (or listed in the
  closing "memo names an invoice" report);
- a line already matched to an invoice/bill is relabelled in place — the
  move stays posted and reconciled, partner and accounts untouched;
- the per-journal summary says "N bare lines healed" and, in yellow, how
  many are still bare because their Monerium order is not known yet.

`chb odoo journals <id> fix --metadata --bare [--dry-run]` runs the same
heal for one journal.

**Stricter hold.** A new EURe mint/burn is pushed only once its Monerium
order is in the cache (memo, moneriumKind/State or the source:monerium
tag). A description coming from a rule or a Nostr annotation no longer
counts: the line would have gone out without the payer's reference.

**Metadata refresh never writes while planning.** `fix --metadata
--dry-run` could create a partner for a counterpart with an unknown IBAN;
partners are now created at apply time only. A counterpart whose exact name
matches one existing partner is linked to it instead of duplicated; several
partners with that name: no partner is set.
