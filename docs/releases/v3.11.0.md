# v3.11.0 — audience tiers: public / members / stewards

Processed data is now written per audience — `YYYY/MM/{public,members,stewards}/`
(and under `YYYY/` and `latest/`): same file names, strictly less in each lower
tier, enforced by directory modes (0755 / 0750 / 0700) and a write-time policy
that refuses third-party IBANs below stewards and masks emails. `stewards/` is
chb's own tree (everything that read `generated/` reads it now); the PII
enrichment file is gone — `stewards/transactions.json` carries it inline.

On first run a pre-tier tree is seeded into `stewards/` and
**`generated/private/` is deleted**. Run `chb generate --history --force` once
to fill `members/` and `public/` for old months. `generated/` keeps being
written for the website until `CHB_LEGACY_GENERATED=0`.
`CHB_MEMBERS_GROUP=<group>` chgrps `members/` to the group the website runs in.

Design, per-artifact classification and open decisions: `docs/audiences.md`.
Website handoff: `docs/website-migration.md`. PR #13.
