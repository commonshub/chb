# v3.34.1 — email mask no longer breaks JSON escapes

- The write-time email mask ran on the encoded JSON and could start a match
  inside an escape sequence: in `"…\n@Leen.v…"` it saw `n@Leen.v` as an
  email and left a lone backslash (`\[email removed]`), making the file
  invalid JSON. Seen in `latest/public/praise.json` right after v3.34.0.
  The escape is now kept and only what follows it is checked (a real
  address after `\n` is still masked).
