# v3.42.0 — Discord members ↔ Odoo partners

Every Discord member with the member role gets an Odoo partner carrying
their Discord id (`res.partner.x_discord_id`), so chb knows who they are,
`members recap` can reach them, and the website can ask those without an
email for one.

- `chb discord partners pull` (read-only): guild members, the website's
  email-hash Discord links, and the emails members gave on the website
  (Nostr kind 30078 `#t partner-email`, signed by the website key,
  NIP-44-encrypted to chb's own partner-email key; newest per `d`).
- `chb discord partners key` creates that key on the server
  (`keys/partner-email.json`, 0600, decryption only) and prints its pubkey.
- `chb discord partners` previews the plan offline. Linking order: a
  partner already carrying the id → `settings/members-discord.json`
  (`odoo:<id>`) → the website's email-hash link (exactly one partner). A
  partner with the same name is listed for review, never linked or
  duplicated. Otherwise a partner is created: not a company, tagged
  "Discord", the Discord display name.
- Emails given on the website are set only on partners chb created whose
  email is empty; anything else (older partners, an email already used by
  another partner) is listed for review. Existing partners only ever get
  `x_discord_id`.
- `chb generate` writes the plan (`latest/providers/odoo/<db>/pending/discord-partners.json`, 0600)
  and `latest/members/discord-partners.json` (`{generatedAt, needsEmail}`,
  Discord ids only) for the website. needsEmail stays empty until Odoo has
  the field.
- `chb discord partners setup [--yes]` creates the field and the tag;
  `chb discord partners push [--yes]` applies the plan (25 per run,
  re-checking live that no other partner carries the id).
- members.json `accounts.discord` is filled from `x_discord_id` (Odoo
  members by partner, Stripe members by email hash).
