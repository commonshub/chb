# VAT declarations (Intervat)

Commons Hub Brussels ASBL (BE0804505132) is a mixed VAT taxpayer and files a
periodic VAT return every quarter with the Belgian federal tax
administration (SPF Finances / FOD Financiën) through **Intervat**. `chb`
archives those returns and publishes them as open data in `vat.json`.

## Importing a declaration

There is no API, so this is a manual import, like the KBC statements.

1. In MyMinfin → Intervat, open the filed declarations and export them as
   XML. Each export is one filed declaration, named like
   `TVA_25092026_12_00_15_STATEMENT_1_69272513.xml`. The trailing number is
   the Intervat **statement id**. The timestamp is only when you exported it.
2. Import them:

   ```
   chb vat import ~/Downloads/TVA_*.xml       # files or directories
   chb vat import --dry-run ~/Downloads/      # preview
   chb vat import                             # or drop them in $DATA_DIR/latest/providers/intervat/ first
   ```

   With no argument the command reads that drop folder and empties it.
3. Check what is archived: `chb vat` (or `chb vat --json`).

Importing is idempotent: the same file again is reported as already
imported. A different file under an already archived statement id is
refused unless you pass `--force`.

## Where the data lives

| path | what | who can read |
|---|---|---|
| `YYYY/MM/providers/intervat/<statementId>.xml` | the export, byte-for-byte. `MM` is the **last month of the period** (Q2 2026 → `2026/06`). | chb only (0700). The declarant block holds the filer's email and phone, often the accountant's own. |
| `YYYY/vat.json` | every period of that year | everyone (0644) |
| `latest/vat.json` | every period ever filed | everyone (0644) |

`vat.json` is regenerated by `chb vat import` and by every `chb generate`.
Because the raw XML sits under the month's `providers/`, it is covered by that
month's `hashes.json` as the `intervat` entry ("2 declarations").

### Why it is public, and outside the tiers

A VAT return is the organisation's own filing with the State: totals per
grid, no counterparties, no personal data. It is the same for every
audience, so, like `hashes.json`, it lives once outside `public/`,
`members/` and `stewards/` rather than as three identical copies. It is
still written under the public tier's policy. The filer's email and phone,
and the declarant's street address, are not copied into it.

## `vat.json`

```json
{
  "generatedAt": "2026-09-25T10:00:00Z",
  "source": "intervat",
  "vatNumber": "BE0804505132",
  "currency": "EUR",
  "gridLabels": { "03": "Operations at 21% (taxable base)", "54": "VAT due on grids 01, 02 and 03", "…": "…" },
  "periods": [
    {
      "period": "2026-Q2", "year": 2026, "quarter": 2,
      "from": "2026-04-01", "to": "2026-06-30",
      "statementId": "69272513",
      "amendments": 1,
      "grids": { "00": 2030.00, "02": 7730.11, "03": 47843.76, "54": 10974.81, "59": 2698.04, "71": 11778.73, "…": 0 },
      "totals": { "outputVat": 15027.64, "inputVat": 3248.91, "due": 11778.73, "credit": 0.00, "net": 11778.73, "consistent": true },
      "filings": [
        { "statementId": "69270977", "sequenceNumber": "1", "declarantName": "CHB", "superseded": true,  "grids": { "…": 0 }, "totals": { "…": 0 } },
        { "statementId": "69272513", "sequenceNumber": "1", "replaces": "1-0804505132-202632", "declarantName": "CHB", "superseded": false, "grids": { "…": 0 }, "totals": { "…": 0 } }
      ]
    }
  ]
}
```

- **`periods`** are sorted oldest first. A quarterly period is `YYYY-Qn`
  with `quarter`; a monthly one would be `YYYY-MM` with `month`.
- **`grids`** are the amounts of the period's effective filing, in euros
  with two decimals, keyed by the two-digit grid number of the official
  form. Grids left empty on the return are absent, which means zero.
  `gridLabels` gives an English label for every grid. `GridOrder` in
  `providers/intervat/intervat.go` is the order of the official form.
- **Corrections.** A period can be filed more than once. The latest filing
  is the effective one: higher statement id, and a filing with `replaces`
  set comes after one without. Top-level `statementId`, `grids` and
  `totals` are the effective filing. `amendments` counts the superseded
  ones, and `filings` keeps all of them for transparency.
- **`totals`** are the return's own control sums:
  `outputVat` = 54 + 55 + 56 + 57 + 61 + 63 (VAT owed),
  `inputVat` = 59 + 62 + 64 (VAT deductible),
  `due` = grid 71 (paid to the State), `credit` = grid 72 (owed by the
  State), `net` = due − credit. `consistent` is false when grid 71 or 72
  does not equal outputVat − inputVat. `chb vat` flags those periods.

### Reading the grids

| grids | meaning |
|---|---|
| 00–03 | our sales, by VAT rate (taxable base): special regime, 6%, 12%, 21% |
| 44–47 | sales without Belgian VAT: EU services, reverse charge, exempt |
| 48–49 | credit notes we issued |
| 81–83 | our purchases: goods, services, investment goods |
| 84–85 | credit notes we received |
| 86–88 | purchases from abroad where we account for the VAT |
| 54–57, 61, 63 | VAT owed |
| 59, 62, 64 | VAT deductible (59 is limited by the pro-rata of a mixed taxpayer) |
| 71 / 72 | balance to pay / to receive |

## Building an interface

- **Overview.** One row per period from `latest/vat.json`: period, sales
  base (00 + 01 + 02 + 03 + 44 + 45 + 46 + 47 − 48 − 49), purchases
  (81 + 82 + 83 − 84 − 85), output VAT, input VAT, `net`. Mark a period
  with `amendments > 0` as corrected and let people expand `filings`.
- **Period detail.** List `grids` in `GridOrder` with `gridLabels`, then the
  `totals` block. Show "paid to the State" for a positive `net` and "refund
  due" for a negative one.
- **Year view.** Read `YYYY/vat.json` and sum `net` over its periods.
- **Freshness.** A quarter's return is filed during the month after the
  quarter ends and then imported by hand. A recent period that is missing
  has not been imported yet; it does not mean nothing was owed.
- Never read `providers/intervat/`: it is 0700 and holds the filer's
  contact details.
